Modern C++ / Module 6

Standard Template Library

The STL gives you battle-tested, zero-overhead containers, iterators, and algorithms — so you spend time on your problem, not on reimplementing sort or search.

Day: 4 of 6Topics: 4 + Story ModeCase study: Student records analyzerRepo folder: 12-DataStrucCollections/

Before STL, C++ programmers chose between raw arrays (fixed size, no bounds checking) or manual dynamic allocation. Sequence containers give you type-safe, growable sequences with correct memory management built in.

WHY

Why fixed arrays aren't enough

A C-style array int arr[100] has fixed size decided at compile time — add a 101st element and you corrupt memory silently.

A raw pointer with new int[n] grows at runtime but has no size tracking, no bounds checking, and requires manual delete[].

Sequence containers solve both: they manage their own memory, track size, provide bounds-checked access (.at()), and clean up automatically.

Choose the right container for the access pattern: vector for random access, list for mid-sequence insertions, deque for both-ends operations.

WHAT

Three sequence containers defined

  • std::vector<T> — dynamic array backed by contiguous memory. O(1) random access (v[i]), amortized O(1) push_back, O(n) insert/erase in middle. Default choice for almost everything.
  • std::list<T> — doubly-linked list. O(1) insert and erase anywhere (given an iterator), but no random access and poor cache locality. Use when you frequently insert/erase inside a large sequence.
  • std::deque<T> — double-ended queue in chunks of memory. O(1) at both ends (push_front AND push_back), O(1) random access. Useful when you need a FIFO queue or stack at one end and indexed access at the other.
  • Capacity vs size: vector has .size() (elements stored) and .capacity() (allocated space). Call v.reserve(n) to pre-allocate and avoid repeated reallocations.
HOW

vector push/iterate/erase, then list mid-insert

step1_sequence.cpp
#include <iostream>
#include <vector>
#include <list>
#include <string>

int main() {
    // --- vector ---
    std::vector<std::string> students;
    students.push_back("Alice");
    students.push_back("Bob");
    students.push_back("Carol");

    students[1] = "Barbara";          // O(1) random access

    for (const auto& name : students)
        std::cout << name << "\n";

    // erase "Barbara" (index 1)
    students.erase(students.begin() + 1);
    std::cout << "After erase: " << students.size() << " students\n\n";

    // --- list ---
    std::list<int> scores = {85, 72, 90};
    auto it = scores.begin();
    ++it;                              // advance to 72
    scores.insert(it, 78);            // insert 78 before 72
    for (int s : scores) std::cout << s << " ";
    std::cout << "\n";
}
Expected outputAlice Barbara Carol After erase: 2 students 85 78 72 90

Run it and experiment

  1. Save as step1_sequence.cpp, compile: g++ -std=c++17 step1_sequence.cpp -o step1
  2. Run: step1.exe (Windows) or ./step1 (Linux/macOS)
  3. Experiment 1: Call students.at(10) — it throws std::out_of_range, while students[10] is undefined behaviour with no error.
  4. Experiment 2: Insert 1000 names in a loop and time it with vector vs list — vector is faster because it is cache-friendly.
  5. Experiment 3: Try students.reserve(100) before the loop and check .capacity() after.
Reference: cppreference — std::vector — capacity management, iterator invalidation rules, and complexity guarantees.

Searching a vector is O(n) — fine for ten items, painful for ten thousand. Associative containers index by key and give you O(log n) or O(1) average lookup.

WHY

Linear search doesn't scale

std::find on a vector of 1M names checks each element until it finds a match: on average 500,000 comparisons per lookup.

A std::map stores keys in a balanced binary search tree — any key lookup is at most log₂(1,000,000) ≈ 20 comparisons regardless of table size.

A std::unordered_map uses a hash table — average O(1) lookup, no ordering. Preferred when order doesn't matter and keys are hashable (strings, ints).

Use a std::set when you only need membership testing (is this name already in the list?) rather than value lookup.

WHAT

Four associative containers

  • std::map<K,V> — sorted BST keyed by K. Iterating gives keys in ascending order. O(log n) insert/find/erase. Use [] to insert or update; use .count(key) or .find() to check without inserting.
  • std::unordered_map<K,V> — hash table. O(1) average. No order. Needs std::hash<K> (built in for string/int/etc). Prefer when order doesn't matter.
  • std::set<T> — sorted unique values. Insert/erase/find O(log n). Useful for deduplication and membership tests.
  • std::unordered_set<T> — hash set. O(1) average membership test. No order.
  • Structured bindings with for (const auto& [k, v] : m) — C++17 syntax that unpacks map pairs.
HOW

Grade lookup by name with map and unordered_map

step2_associative.cpp
#include <iostream>
#include <map>
#include <unordered_map>
#include <string>

int main() {
    // map: sorted by key
    std::map<std::string, int> grades;
    grades["Alice"] = 92;
    grades["Bob"]   = 78;
    grades["Carol"] = 85;
    grades["David"] = 91;

    // Iterates in alphabetical key order
    for (const auto& [name, grade] : grades)
        std::cout << name << ": " << grade << "\n";

    // Safe lookup (never inserts a default)
    if (grades.count("Eve") == 0)
        std::cout << "Eve not enrolled\n";

    auto it = grades.find("Bob");
    if (it != grades.end())
        std::cout << "Bob's grade: " << it->second << "\n";

    // unordered_map: O(1) average, no order guarantee
    std::unordered_map<std::string, int> ids = {
        {"Alice", 1001}, {"Bob", 1002}
    };
    std::cout << "Alice's ID: " << ids["Alice"] << "\n";
}
Expected outputAlice: 92 Bob: 78 Carol: 85 David: 91 Eve not enrolled Bob's grade: 78 Alice's ID: 1001

Every program eventually sorts a list or searches for an item. The <algorithm> header provides correct, optimized implementations of these operations — generic across all containers that provide iterators.

WHY

Don't rewrite sort and search

A hand-written bubble sort is O(n²). std::sort uses introsort — O(n log n) average and worst case. Using the standard version costs zero extra lines and gives you production-tested code.

All STL algorithms work through iterators. The same std::sort that sorts a vector also sorts an array. The same std::find_if that searches a list also searches a deque. No specialization needed.

Algorithms compose: std::transform + std::accumulate expresses a map-reduce pipeline in two lines without any index variables.

WHAT

Six essential algorithms

  • std::sort(begin, end) — sorts in ascending order in-place. O(n log n).
  • std::sort(begin, end, comparator) — sorts by a custom predicate. Comparator returns true if first arg comes before second.
  • std::find_if(begin, end, pred) — returns iterator to first element where pred(elem) is true, or end if none matches.
  • std::count_if(begin, end, pred) — returns count of elements satisfying predicate.
  • std::transform(in_begin, in_end, out_begin, op) — applies op to each input element, writing results to output. Use std::back_inserter(v) as out_begin to append to a vector.
  • std::accumulate(begin, end, init) — folds the range with + starting from init. In <numeric>.
HOW

Sort, find, count and average a student list

step3_algorithms.cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <numeric>
#include <string>

struct Student { std::string name; int grade; };

int main() {
    std::vector<Student> students = {
        {"Alice", 92}, {"Bob", 78}, {"Carol", 85}, {"David", 91}
    };

    // Sort by grade descending
    std::sort(students.begin(), students.end(),
              [](const Student& a, const Student& b){ return a.grade > b.grade; });

    std::cout << "Ranked:\n";
    for (const auto& s : students)
        std::cout << "  " << s.name << ": " << s.grade << "\n";

    // First student with grade >= 90
    auto top = std::find_if(students.begin(), students.end(),
                            [](const Student& s){ return s.grade >= 90; });
    if (top != students.end())
        std::cout << "Top scorer: " << top->name << "\n";

    // Count passing (>= 80)
    int passing = std::count_if(students.begin(), students.end(),
                                [](const Student& s){ return s.grade >= 80; });
    std::cout << "Passing: " << passing << "/" << students.size() << "\n";

    // Average grade via transform + accumulate
    std::vector<int> scores;
    std::transform(students.begin(), students.end(),
                   std::back_inserter(scores),
                   [](const Student& s){ return s.grade; });
    double avg = static_cast<double>(
        std::accumulate(scores.begin(), scores.end(), 0)) / scores.size();
    std::cout << "Average: " << avg << "\n";
}
Expected outputRanked: Alice: 92 David: 91 Carol: 85 Bob: 78 Top scorer: Alice Passing: 3/4 Average: 86.5

  3. Experiment 2: Use std::min_element / std::max_element with the same lambda comparator to find the bottom and top scores in one call each.
  4. Experiment 3: Replace the transform+accumulate pair with std::reduce (C++17, also in <numeric>) and compare.

Iterators are the bridge between containers and algorithms. An algorithm never knows which container it is working on — it only knows how to advance an iterator and dereference it. That one abstraction makes every algorithm work with every container.

WHY

Why algorithms don't take containers

If std::sort accepted std::vector directly, you would need a separate listSort, dequeSort, and arraySort. That defeats the purpose of a generic library.

Iterators define a uniform vocabulary: *it dereferences, ++it advances, it != end tests for completion. Any type that satisfies those operations works with any algorithm that needs them.

begin(c) and end(c) give iterators to the first element and one-past-the-last — this half-open range [begin, end) is the universal convention throughout the STL.

WHAT

Iterator categories and key operations

  • Input/Output iterators: single-pass read or write. std::istream_iterator and std::ostream_iterator are examples.
  • Forward iterators: multi-pass forward traversal. std::list and std::forward_list iterators.
  • Bidirectional iterators: forward and backward (--it). std::list, std::map iterators.
  • Random-access iterators: jump by n in O(1) (it + 5, it - 3). std::vector and std::deque iterators.
  • rbegin() / rend() — reverse iterators; ++ on a reverse iterator moves backward through the container.
  • std::back_inserter(v) — an output iterator adapter that calls push_back on every assignment. Lets algorithms write into a vector without pre-sizing it.
HOW

Forward, reverse, copy, and filter with iterators

step4_iterators.cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <iterator>

int main() {
    std::vector<int> scores = {85, 92, 78, 91, 88};

    // Forward iteration via explicit iterators
    std::cout << "Forward:  ";
    for (auto it = scores.begin(); it != scores.end(); ++it)
        std::cout << *it << " ";
    std::cout << "\n";

    // Reverse iteration
    std::cout << "Reversed: ";
    for (auto it = scores.rbegin(); it != scores.rend(); ++it)
        std::cout << *it << " ";
    std::cout << "\n";

    // Copy to stdout with ostream_iterator
    std::cout << "Copy:     ";
    std::copy(scores.begin(), scores.end(),
              std::ostream_iterator<int>(std::cout, " "));
    std::cout << "\n";

    // Filter with back_inserter -- no manual push_back loop needed
    std::vector<int> high;
    std::copy_if(scores.begin(), scores.end(),
                 std::back_inserter(high),
                 [](int s){ return s >= 90; });
    std::cout << "High (>=90):";
    for (int s : high) std::cout << " " << s;
    std::cout << "\n";
}
Expected outputForward: 85 92 78 91 88 Reversed: 88 91 78 92 85 Copy: 85 92 78 91 88 High (>=90): 92 91

Run it and experiment

  1. Compile: g++ -std=c++17 step4_iterators.cpp -o step4, run.
  2. Experiment 1: Add std::sort(scores.begin(), scores.end()) before the forward loop — observe that the reversed output is now also sorted, because reverse iterators traverse the same (now-sorted) data backward.
  3. Experiment 2: std::distance(scores.begin(), scores.end()) returns the element count — useful with containers that have no .size().
  4. Experiment 3: Try std::advance(it, 3) — moves any iterator forward by 3 steps, and backward for bidirectional/random-access iterators.

🎬 Story Mode

The records that couldn't be found

Nimbus Academy started the year with student records in a spreadsheet. As enrolment grew to 800 students and quizzes multiplied, the Python script that sorted the sheet began to time out — and a professor querying a single student had to wait 40 seconds. The engineering team rewrote the system in C++ using exactly the containers, algorithms, and iterators you just studied.

ACT 1 — The list that kept growing  

The academy stored names in a fixed-size array. When a late-registration student arrived as the 201st enrolment, the code wrote past the end of the array and silently corrupted the grade records three positions later. Replacing the array with a std::vector took one line of change: capacity grew automatically, bounds-checking via .at() caught any out-of-range access immediately, and the corruption bug disappeared permanently.

ACT 2 — Eight hundred lookups, forty seconds  

The grade-reporting endpoint searched a vector of 800 students with std::find every time a professor queried a name. On a quiet afternoon with 20 concurrent users, response time hit 40 seconds. Replacing the vector with a std::map<string, Student> cut lookup from O(n) to O(log n) — 800 students means at most 10 comparisons per query instead of up to 800. Response time dropped to under 2 milliseconds.

ACT 3 — Ranking day  

Each semester the academy produced a ranked report of all students sorted by average quiz score, with a count of passing students and the cohort average. The first version used nested for loops and a hand-written bubble sort — 60 lines, one subtle off-by-one bug. The rewrite used std::sort with a lambda comparator, std::count_if, and std::accumulate from <numeric> — 6 lines, no off-by-one possible, and O(n log n) instead of O(n²).

ACT 4 — Outputting to any sink  

The final report needed to be sent to the terminal, to a file, and to an HTTP response body — three different output targets. Without iterators, each target would need its own copy of the formatting loop. With std::ostream_iterator, the same std::copy call writes to any output stream: std::cout, a std::ofstream, or a std::ostringstream. One algorithm, three sinks.

The STL isn't a collection of types — it is a vocabulary that makes every algorithm speak to every container and every output sink.

Also seen in the wild

FinancePortfolio risk engines store positions in unordered_map<string, Position> for O(1) lookup during live trading — milliseconds matter.
HealthcarePatient scheduling systems use std::priority_queue to always serve the next highest-priority patient without sorting the full queue each time.
Game enginesEntity-component systems keep component arrays in std::vector for cache-friendly iteration — 10,000 enemies updated per frame without a single heap allocation per enemy.
Embedded systemsFixed-size ring buffers implemented as std::array + iterators let firmware process sensor data with zero dynamic allocation.

Step 3Sort by average and count passing

Combine sort with a custom comparator and count_if in one program.

step3_rank.cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <numeric>
#include <string>
struct S { std::string name; std::vector<int> scores; };
int avg(const S& s){
    return std::accumulate(s.scores.begin(),s.scores.end(),0)/s.scores.size();
}
int main() {
    std::vector<S> r = {{"Alice",{92,88,95}},{"Bob",{72,68,75}},{"Carol",{85,89,82}}};
    std::sort(r.begin(), r.end(), [](const S& a, const S& b){ return avg(a) > avg(b); });
    for (const auto& s : r) std::cout << s.name << ": " << avg(s) << "\n";
    int pass = std::count_if(r.begin(),r.end(),[](const S& s){return avg(s)>=80;});
    std::cout << pass << "/" << r.size() << " passing\n";
}

Run: g++ -std=c++17 step3_rank.cpp -o step3

Student records analyzer — map lookup + sort + stats in one program

A complete analyzer combining all four STL concepts: map for lookup, sort with a lambda, count_if for passing rate, and accumulate for the average.

program.cpp — complete use case
#include <iostream>
#include <vector>
#include <map>
#include <algorithm>
#include <numeric>
#include <string>
#include <iomanip>

struct Student {
    std::string name;
    std::vector<int> quizScores;

    double average() const {
        if (quizScores.empty()) return 0.0;
        return static_cast<double>(
            std::accumulate(quizScores.begin(), quizScores.end(), 0))
            / quizScores.size();
    }
};

void printReport(const std::vector<Student>& roster) {
    auto sorted = roster;
    std::sort(sorted.begin(), sorted.end(),
              [](const Student& a, const Student& b){
                  return a.average() > b.average();
              });

    std::cout << std::left
              << std::setw(10) << "Name"
              << std::setw(10) << "Average"
              << "Status\n"
              << std::string(30, '-') << "\n";

    for (const auto& s : sorted) {
        std::string status = s.average() >= 80.0 ? "PASS" : "FAIL";
        std::cout << std::setw(10) << s.name
                  << std::setw(10) << std::fixed << std::setprecision(1)
                  << s.average()
                  << status << "\n";
    }

    int passing = std::count_if(sorted.begin(), sorted.end(),
                                [](const Student& s){ return s.average() >= 80.0; });
    std::cout << "\n" << passing << " of " << sorted.size()
              << " students passed.\n";

    auto best = std::max_element(sorted.begin(), sorted.end(),
                                 [](const Student& a, const Student& b){
                                     return a.average() < b.average();
                                 });
    std::cout << "Top scorer: " << best->name
              << " (" << std::fixed << std::setprecision(1)
              << best->average() << ")\n";
}

int main() {
    std::vector<Student> roster = {
        {"Alice",  {92, 88, 95, 90}},
        {"Bob",    {72, 68, 75, 70}},
        {"Carol",  {85, 89, 82, 88}},
        {"David",  {91, 94, 88, 93}},
        {"Eva",    {78, 76, 80, 79}},
    };

    // Quick lookup by name using map
    std::map<std::string, int> nameIndex;
    for (int i = 0; i < static_cast<int>(roster.size()); ++i)
        nameIndex[roster[i].name] = i;

    std::string query = "Carol";
    if (nameIndex.count(query))
        std::cout << query << "'s average: "
                  << std::fixed << std::setprecision(1)
                  << roster[nameIndex[query]].average() << "\n\n";

    printReport(roster);
}
Expected outputCarol's average: 86.0 Name Average Status ------------------------------ David 91.5 PASS Alice 91.3 PASS Carol 86.0 PASS Eva 78.3 FAIL Bob 71.3 FAIL 3 of 5 students passed. Top scorer: David (91.5)
