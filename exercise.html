Practice / Capstone Exercise

Capstone Exercise: RR Skillverse Course Tracker

You have already practiced classes, access control, constructors and destructors, static members, friend functions, inheritance, virtual dispatch, abstract classes, and overloading — one idea at a time, on their own small examples. This exercise is the first place all of it has to work together, on one program, for a use case that isn't a shape or a bank account.

Brings together: classes → inheritance → overloadingCase study: RR Skillverse course trackerEstimated time: 45-60 minutesRepo file: 08-ClassesandObjects/rr_skillverse_course_tracker.cpp

Picture this: you have just joined the engineering team at RR Skillverse — a platform Raushan built on one idea: learning should be accessible, interesting, and available to everyone. Every learner is enrolled in a course, but not every course works the same way — a self-paced video course is "done" once you've watched enough of it, a live workshop is "done" once you've shown up to enough sessions. The platform needs to track every learner's progress in whichever format they chose, let a learner ask for a bit more time when life gets in the way, and hand out a certificate the moment someone actually finishes — automatically, correctly, for every course format, including ones that don't exist yet.

What this exercise pulls together

Classes & objectsOne Course type owns its own learner data and behavior, instead of that data and the logic that uses it living in separate places.
Constructors, destructors & static membersConstructors and destructors log every enrollment and exit, while a static counter keeps one platform-wide enrollment total in sync no matter how many courses exist. A friend function issues certificates by reading a learner's progress directly.
Inheritance & abstract classesAn abstract Course base class with virtual functions and a virtual destructor lets every course format be tracked and cleaned up through one shared interface.
Function & operator overloadingOverloaded requestExtraTime() functions and overloaded operator+/operator<< give the tracker a natural, calculator-like API.
WHY

Why one base class for every course format

RR Skillverse offers a growing list of course formats — self-paced video today, live workshops too, more later. Enrollment tracking, cleanup, and certificate logic should not need a special case for every format that gets added. So every course is a Course first: one abstract base class defines what a course must be able to do (say whether it's complete, describe its own progress, estimate its weekly time commitment), and each concrete format decides for itself what "complete" actually means.

The base class also owns something no single course should own alone: a static, platform-wide count of active enrollments and certificates issued. Every constructor and destructor keeps that shared dashboard honest — the same discipline you already practiced with a shared account counter, just applied to a very different problem.

WHAT

The complete sample program

This program compiles and runs as-is. Read it top to bottom before touching anything — it is the pattern your homework will extend, not a blank page.

rr_skillverse_course_tracker.cpp
// Capstone exercise sample -- combines everything from classes and access
// control through inheritance, virtual dispatch, abstract classes, and
// overloading in one program.
//
// Use case: RR Skillverse, a platform built to make learning accessible,
// interesting, and available to everyone -- tracking a learner's progress
// in a course, granting extra time when someone needs it, and issuing a
// certificate the moment a course is actually finished.
#include <iostream>
#include <string>
using namespace std;

// Every course format on RR Skillverse is a Course first (inheritance).
class Course {
protected:
    string learnerName;
    string courseTitle;
    int daysExtended = 0;

    // Static members: one shared, platform-wide dashboard for every course object.
    static int totalEnrollments;
    static int totalCertificatesIssued;

public:
    Course(const string& learner, const string& title)
        : learnerName(learner), courseTitle(title) {
        ++totalEnrollments;
        cout << "[enrolled] " << learnerName << " joined \"" << courseTitle << "\"\n";
    }

    // Virtual destructor: safe cleanup through a base pointer/reference.
    virtual ~Course() {
        --totalEnrollments;
        cout << "[exited] " << learnerName << " left \"" << courseTitle << "\"\n";
    }

    // Pure virtual functions: every concrete course must define its own contract (abstract class).
    virtual bool isComplete() const = 0;
    virtual string statusLine() const = 0;
    virtual double weeklyHours() const = 0;

    // Function overloading: two different ways to grant a learner extra time.
    void requestExtraTime(int days) {
        daysExtended += days;
    }
    void requestExtraTime(int days, const string& reason) {
        daysExtended += days;
        cout << "  " << learnerName << " granted " << days << " extra day(s): " << reason << "\n";
    }

    static int enrollmentCount() { return totalEnrollments; }
    static int certificatesIssued() { return totalCertificatesIssued; }

    // Friend function: certificate issuing needs direct access to protected learner/course data.
    friend void issueCertificateIfComplete(const Course& course);

    friend ostream& operator<<(ostream& out, const Course& course) {
        out << course.learnerName << " -> " << course.courseTitle
            << " [" << course.statusLine() << "]";
        return out;
    }

    // Operator overloading: combine two enrollments into one weekly study-hours estimate.
    friend double operator+(const Course& a, const Course& b) {
        return a.weeklyHours() + b.weeklyHours();
    }
};

int Course::totalEnrollments = 0;
int Course::totalCertificatesIssued = 0;

void issueCertificateIfComplete(const Course& course) {
    if (course.isComplete()) {
        ++Course::totalCertificatesIssued;
        cout << "  Certificate issued to " << course.learnerName
             << " for \"" << course.courseTitle << "\"\n";
    } else {
        cout << "  Not yet eligible for a certificate: " << course.learnerName << "\n";
    }
}

class VideoCourse : public Course {
    double percentWatched;
public:
    VideoCourse(const string& learner, const string& title, double percent)
        : Course(learner, title), percentWatched(percent) {}
    bool isComplete() const override { return percentWatched >= 90.0; }
    string statusLine() const override {
        return "self-paced video, " + to_string((int)percentWatched) + "% watched";
    }
    double weeklyHours() const override { return 2.5; }
};

class LiveWorkshop : public Course {
    int sessionsAttended;
    int totalSessions;
public:
    LiveWorkshop(const string& learner, const string& title, int attended, int total)
        : Course(learner, title), sessionsAttended(attended), totalSessions(total) {}
    bool isComplete() const override { return sessionsAttended >= totalSessions; }
    string statusLine() const override {
        return "live workshop, " + to_string(sessionsAttended) + "/" +
               to_string(totalSessions) + " sessions attended";
    }
    double weeklyHours() const override { return totalSessions * 1.5; } // 1.5 hrs per session
};

int main() {
    VideoCourse meera("Meera", "C++ Foundations", 92.0);
    LiveWorkshop dev("Dev", "C++ Mentorship Circle", 3, 4);

    cout << meera << "\n";
    cout << dev << "\n";

    dev.requestExtraTime(3, "exam week conflict"); // second overload

    cout << "Combined weekly study hours for Meera+Dev: " << (meera + dev) << "\n";

    issueCertificateIfComplete(meera);
    issueCertificateIfComplete(dev);

    cout << "Active enrollments: " << Course::enrollmentCount() << "\n";
    cout << "Certificates issued so far: " << Course::certificatesIssued() << "\n";
}
Expected output[enrolled] Meera joined "C++ Foundations" [enrolled] Dev joined "C++ Mentorship Circle" Meera -> C++ Foundations [self-paced video, 92% watched] Dev -> C++ Mentorship Circle [live workshop, 3/4 sessions attended] Dev granted 3 extra day(s): exam week conflict Combined weekly study hours for Meera+Dev: 8.5 Certificate issued to Meera for "C++ Foundations" Not yet eligible for a certificate: Dev Active enrollments: 2 Certificates issued so far: 1 [exited] Dev left "C++ Mentorship Circle" [exited] Meera left "C++ Foundations"

Run it in VS Code

  1. Create a folder named capstone-exercise and open it in VS Code.
  2. Save the code above as rr_skillverse_course_tracker.cpp (it also lives in the repo at 08-ClassesandObjects/rr_skillverse_course_tracker.cpp).
  3. Compile with g++ -std=c++17 rr_skillverse_course_tracker.cpp -o tracker.
  4. Run tracker.exe on Windows or ./tracker on Linux/macOS.
  5. Compare your terminal output line-by-line against the expected output above before you change anything.
Before you extend it: find the line that decides whether Meera gets a certificate, and explain out loud why Dev does not get one even after the extra days are granted. If that's clear, you understand exactly what isComplete() is for — and you are ready for the task below.
HOW

Your task

Homework / assessment

Add a ReadingGroup course, then a third way to request extra time

RR Skillverse just launched its first peer-led format — a small reading group that works through a fixed list of articles together, with no video and no live sessions. It needs its own definition of "complete," but it should show up correctly everywhere a Course already works: the << printout, the + combined study-hours total, and the certificate check.

  1. Add a class ReadingGroup that inherits from Course and stores how many articles a learner has read and how many the group has in total.
  2. Implement isComplete(), statusLine(), and weeklyHours() so they describe a reading group instead of a video or a workshop.
  3. Create one ReadingGroup in main(), print it, include it in a combined weekly-hours total with another course, and pass it to issueCertificateIfComplete().
  4. Add a third overload of requestExtraTime() that takes no arguments at all and grants a fixed, default number of days — print a confirmation message from inside it.
  5. Re-run the program and confirm Course::enrollmentCount() reports 3 active enrollments instead of 2.

Hints, not the answer

  • Your ReadingGroup constructor only needs to pass the learner name and title up to Course's constructor — articles-read and total-articles are extra members that your overrides read when they do their own work, the same way LiveWorkshop already reads its own session counts.
  • You should not need to touch operator+, operator<<, or issueCertificateIfComplete() at all. If a correctly written ReadingGroup doesn't automatically work with all three, something about your override is wrong — check that every pure virtual function is actually implemented with a matching signature.
  • A zero-argument requestExtraTime() is already unambiguous next to the other two overloads purely by how many arguments are passed — the compiler never has to guess which one you meant.
  • Decide what "complete" honestly means for a reading group before you write isComplete() — keep the comparison as direct as VideoCourse and LiveWorkshop already are.
