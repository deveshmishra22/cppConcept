Robustness / Module 5

Templates & Generics

Write an algorithm or data structure once and compile it correctly for any type that supports the required operations — without duplicating code or losing type safety.

Day: 3 of 6Topics: 4 + Story ModeCase study: Generic inventory stackRepo folder: 12-DataStrucCollections/

Before templates, writing type-independent code meant choosing between unsafe type casting or tedious code duplication. Templates eliminate both choices.

WHY

The duplication that templates replace

Suppose you need a max() function for int, double, and std::string. Without templates you write three separate functions — same logic, different type in the signature. When the logic has a bug, you fix it in three places. When you add float support, you add a fourth copy. After six types, six functions that must stay in sync.

Templates solve this by parameterising the type: write the logic once, and the compiler generates a concrete function for each type used at a call site. Generation happens at compile time, produces the same native code as hand-written versions, and adds zero runtime overhead — the compiler does the duplication, correctly, every time.

The entire C++ Standard Template Library — std::vector, std::map, std::sort, std::unique_ptr — is built on this single idea.

WHAT

Key terms defined

  • template<typename T> — declares T as a type parameter. You can use T anywhere inside the template as a placeholder for the concrete type provided at usage.
  • template instantiation — when the compiler sees maxOf(3, 5) it generates a concrete maxOf<int>(int, int) function from the template. This is compile-time code generation; no runtime dispatch occurs.
  • typename vs class — in a template parameter list, both keywords are identical: template<typename T> and template<class T> mean the same thing. Prefer typename for clarity in modern code.
  • Template headers — templates must be fully defined in header files (.h), not split across a .cpp. The compiler needs the full definition at every usage point to generate the instantiation.
  • Compile-time contract — if you call maxOf(a, b) where T doesn't support >, you get a compile-time error. The template imposes a contract on T enforced at instantiation.
HOW

Three versions of max(), then one template

See the duplication problem, then see it erased — both in the same file:

step1_why_templates.cpp
#include <iostream>
#include <string>

// WITHOUT templates — three identical functions, one per type
int    maxInt   (int a,    int b)    { return a > b ? a : b; }
double maxDouble(double a, double b) { return a > b ? a : b; }
std::string maxStr(const std::string& a, const std::string& b) {
    return a > b ? a : b;
}

// WITH templates — one definition for all types that support >
template<typename T>
const T& maxOf(const T& a, const T& b) { return a > b ? a : b; }

int main() {
    // Old way: caller must know which name to use
    std::cout << maxInt(3, 7)              << "\n"; // 7
    std::cout << maxDouble(3.14, 2.71)     << "\n"; // 3.14
    std::cout << maxStr("zebra", "apple")  << "\n"; // zebra

    // New way: compiler deduces T from argument types
    std::cout << maxOf(3, 7)               << "\n"; // int — 7
    std::cout << maxOf(3.14, 2.71)         << "\n"; // double — 3.14
    std::cout << maxOf<std::string>("zebra", "apple") << "\n"; // zebra
    std::cout << maxOf('a', 'z')           << "\n"; // char — z
}
Expected output7 3.14 zebra 7 3.14 zebra z

Run it and experiment

  1. Save as step1_why_templates.cpp, compile: g++ -std=c++17 step1_why_templates.cpp -o step1
  2. Run: step1.exe (Windows) or ./step1 (Linux/macOS)
  3. Experiment 1: Call maxOf(1, 2.5) — the compiler cannot deduce T because arguments are different types (int and double). Fix it with maxOf<double>(1, 2.5) to provide T explicitly.
  4. Experiment 2: Try calling maxOf with a struct that has no operator> defined — read the compile error carefully. It tells you exactly which operator is missing and why the instantiation failed.

A function template is a pattern — the compiler stamps out one concrete function per unique set of type arguments seen across the program.

WHY

Type safety without void*

Before templates, generic utilities in C used void* — you cast in and out. This worked but was type-unsafe: nothing prevented storing a float* value in a container intended for int*, and the bug appeared at runtime as a corrupted read, not at compile time as a type error.

Function templates give you the same write-once capability with complete type safety — the generated function knows exactly which type it's working with at every operation, and the compiler rejects misuse at compile time before the program ever runs.

WHAT

Syntax, deduction, and parameter passing

  • template<typename T> on the line immediately before the function — T is valid for that function only.
  • const T& as parameter type — pass by const reference to avoid copying large objects; T might be a heavy class like std::vector.
  • Type deduction — the compiler infers T from the argument types. swap(x, y) where x and y are int deduces T=int automatically.
  • Explicit template argument — maxOf<double>(a, b) forces T=double; use when deduction would be ambiguous or wrong.
  • Non-type parameters — template<int N> allows compile-time integer constants. Used for fixed-size arrays and compile-time loop bounds.
HOW

Reusable swap and clamp for any type

step2_function_template.cpp
#include <iostream>
#include <string>

template<typename T>
void swapValues(T& first, T& second) {
    T temp = first;
    first  = second;
    second = temp;
}

template<typename T>
const T& clamp(const T& value, const T& lo, const T& hi) {
    if (value < lo) return lo;
    if (value > hi) return hi;
    return value;
}

int main() {
    int x = 10, y = 20;
    std::cout << "Before: " << x << ", " << y << "\n";
    swapValues(x, y);
    std::cout << "After:  " << x << ", " << y << "\n";

    std::cout << clamp(150, 0, 100) << "\n"; // 100  (clamped to hi)
    std::cout << clamp(-5,  0, 100) << "\n"; // 0    (clamped to lo)
    std::cout << clamp(50,  0, 100) << "\n"; // 50   (unchanged)

    std::string a = "hello", b = "world";
    swapValues(a, b);
    std::cout << a << " " << b << "\n";       // world hello
}
Expected outputBefore: 10, 20 After: 20, 10 100 0 50 world hello

Run it and experiment

  1. Compile: g++ -std=c++17 step2_function_template.cpp -o step2, run.
  2. Experiment 1: Call clamp(3.5f, 0.0f, 1.0f) — works with float without any new code.
  3. Experiment 2: Call swapValues(x, a) (int and string) — the compiler error shows T cannot be deduced when arguments have different types. This is the type-safety guarantee working.
  4. Experiment 3: Note that std::swap and std::clamp (C++17) already exist in the standard library — compare their signatures to yours.
Reference: cppreference: std::clamp — the standard library version of this template, available since C++17.

A class template parameterises an entire class on one or more types — the same pattern the standard library uses for std::vector, std::map, and std::unique_ptr.

WHY

Data structures shouldn't know what they store

A stack that works only for int forces you to write a separate stack for double, string, or any domain object. The logic — push, pop, peek, check-empty — is identical for all of them. Parameterising the element type with a template lets you write the logic once and instantiate it for any type that can be stored in a std::vector.

The same reasoning applies to every container in the standard library: std::vector<T>, std::map<K,V>, std::queue<T> are all class templates. Understanding how to write one lets you read and use the standard library fluently.

WHAT

Class template syntax and instantiation

  • template<typename T> immediately before the class definition parameterises the whole class on T.
  • Member functions defined outside the class body repeat the template header: template<typename T> void Stack<T>::push(const T& item).
  • Distinct instantiations — Stack<int> and Stack<double> are two separate types. They don't share state or vtable entries.
  • Multiple type parameters — template<typename K, typename V> for map-like types that key and value separately.
  • Since templates must be in headers, a common pattern is Stack.h containing both the class declaration and all member function definitions.
HOW

A generic Stack<T> with exception safety

step3_stack_template.cpp
#include <iostream>
#include <vector>
#include <stdexcept>
#include <string>

template<typename T>
class Stack {
    std::vector<T> data_;
public:
    void push(const T& item) { data_.push_back(item); }

    T pop() {
        if (empty())
            throw std::underflow_error("Stack is empty");
        T top = data_.back();
        data_.pop_back();
        return top;
    }

    const T& peek() const {
        if (empty())
            throw std::underflow_error("Stack is empty");
        return data_.back();
    }

    bool        empty() const { return data_.empty(); }
    std::size_t size()  const { return data_.size(); }
};

int main() {
    Stack<int> nums;
    nums.push(10);
    nums.push(20);
    nums.push(30);

    std::cout << "Top: " << nums.peek() << "\n";
    while (!nums.empty())
        std::cout << "Pop: " << nums.pop() << "\n";

    Stack<std::string> words;
    words.push("first");
    words.push("second");
    words.push("third");
    std::cout << "Size: " << words.size() << "  Top: " << words.peek() << "\n";

    try {
        while (true) words.pop();  // empties then throws
    }
    catch (const std::underflow_error& e) {
        std::cout << "Caught: " << e.what() << "\n";
    }
}
Expected outputTop: 30 Pop: 30 Pop: 20 Pop: 10 Size: 3 Top: third Caught: Stack is empty

Every container and algorithm in the C++ Standard Template Library is a template — understanding this makes the STL predictable rather than magical.

WHY

The STL as applied template design

The entire Standard Template Library was designed around one insight: containers and algorithms should work with any type that satisfies a minimal contract. std::vector<T> requires T to be copyable or movable. std::sort requires iterators and an operator<. std::map<K,V> requires K to support operator<. The contracts are enforced at compile time through template instantiation — a type violation gives you a compile error, not a runtime crash.

Recognising that these are templates explains why you write std::vector<int> and not just std::vector, why std::optional<int> and std::optional<std::string> behave differently, and why the standard library can be extended — by writing a type that satisfies the right contracts.

WHAT

Key standard templates to know

  • std::vector<T> — resizable array. O(1) amortised push_back, O(1) random access, O(n) insert at arbitrary position.
  • std::map<Key, Value> — sorted associative container (red-black tree). O(log n) insert and lookup. Key must support operator<.
  • std::unordered_map<Key, Value> — hash table. O(1) average insert and lookup. Key must be hashable.
  • std::optional<T> (C++17) — holds either a T or nothing (std::nullopt). Use instead of returning -1 or nullptr as "not found".
  • std::pair<A, B> and std::tuple<Types...> — bundle multiple values without a custom struct.
  • std::unique_ptr<T> — RAII smart pointer. The sole owner of a heap-allocated T. Move-only; cannot be copied.
  • std::sort, std::find_if, std::count_if — algorithm templates that work with any iterator range whose elements support the required operation.
HOW

std::vector, std::map, and std::optional in one program

step4_stl_templates.cpp
#include <iostream>
#include <vector>
#include <map>
#include <optional>
#include <algorithm>

// Returns the first score above the threshold — or nothing
std::optional<int> findFirstAbove(const std::vector<int>& scores, int threshold) {
    for (int s : scores)
        if (s > threshold) return s;
    return std::nullopt;  // "nothing found"
}

int main() {
    // vector<T> — sorted in place
    std::vector<int> scores = {72, 85, 91, 60, 95, 78};
    std::sort(scores.begin(), scores.end());
    std::cout << "Sorted: ";
    for (int s : scores) std::cout << s << " ";
    std::cout << "\n";

    // map<K,V> — sorted by key automatically
    std::map<std::string, int> grades;
    grades["Alice"] = 92;
    grades["Bob"]   = 85;
    grades["Carol"] = 91;
    for (const auto& [name, grade] : grades)
        std::cout << name << ": " << grade << "\n";

    // optional<T> — explicit "found or not"
    auto found = findFirstAbove(scores, 90);
    if (found)
        std::cout << "First above 90: " << *found << "\n";

    auto notFound = findFirstAbove(scores, 100);
    if (!notFound)
        std::cout << "None above 100\n";
}
Expected outputSorted: 60 72 78 85 91 95 Alice: 92 Bob: 85 Carol: 91 First above 90: 91 None above 100

Run it and experiment

  1. Compile: g++ -std=c++17 step4_stl_templates.cpp -o step4, run.
  2. Experiment 1: Change std::map to std::unordered_map — the output order changes (hash maps aren't sorted), but the lookup is O(1) average instead of O(log n).
  3. Experiment 2: Replace findFirstAbove with std::find_if from <algorithm>: auto it = std::find_if(scores.begin(), scores.end(), [threshold](int s){ return s > threshold; });. Compare the two approaches.
  4. Experiment 3: Use std::count_if to count how many scores are above 80 — one line, no loop.

🎬 Story Mode

The copy that drifted

The data team at Nimbus Analytics built a sorting and search pipeline for integer metrics. Then marketing needed it for string labels. Then finance needed it for decimal values. Within a month, three nearly identical codebases existed. Then a bug was found and fixed in the integer version. One developer forgot to apply it to the string version. The decimal version never got the fix at all. They had three codebases to maintain and none of them matched. This module is how one function replaced all three.

When the finance team asked for a fourth variant — boolean flags this time — the lead engineer refused to copy the code again. Her argument: the algorithm is identical across all four versions. Only the type changes. That means the type should be the variable, not the code. A template is C++'s way of making that happen. You write the code once with a placeholder type T, and the compiler generates a concrete version for each type you actually use. One source. Many generated implementations. Every bug fix applies everywhere automatically.

The pipeline had a findMax() function that found the largest value in a dataset. As a function template — written with template<typename T> before the function — it works for int, double, and string without a single cast or branch. When the team writes findMax(intData), the compiler sees the argument is int and generates a concrete findMax(vector<int>). When they write findMax(stringData), it generates the string version. Same source code. Correct implementation for each type. Zero runtime overhead — everything is decided at compile time.

The pipeline also needed a stack to hold pending items for processing. The push, pop, and peek logic is exactly the same regardless of what type is being stored. Written as a class template — template<typename T> class Stack — it works for integer event codes, string labels, or complex structs. You write the logic once. When you write Stack<int> the compiler generates a concrete integer stack; Stack<string> generates a string stack. Both are as efficient as if someone had written them by hand — because the compiler did.

After a sprint of building generic containers, a senior engineer opened the C++ standard library documentation and pointed at the screen. std::vector<T>. std::map<K, V>. std::optional<T>. std::stack<T>. All of them are templates, all already written and battle-tested, all zero overhead. The lesson is not that templates are hard to write — it is that understanding how templates work is what makes the standard library readable. You recognize the angle-bracket pattern, you know what T means, and suddenly the STL is not magic anymore. You have been using templates since your very first vector<int>. What we just learned

  • Template — code where the type is a variable (T); the compiler generates a concrete version for each type you use it with
  • Function template — template<typename T> before a function; the compiler deduces T from the argument types at the call site
  • Class template — template<typename T> class Stack; instantiated with Stack<int> or Stack<string>; logic written once, type-specific classes generated by the compiler
  • Template instantiation — when the compiler generates a real function or class from a template for a specific type; happens at compile time, not runtime
  • STL — the standard library is a collection of template classes and functions; vector<T>, map<K,V>, optional<T> are all templates you can now read and extend

Also seen in the wild

FinanceA risk calculator templated on market data type — equity, bond, derivative — avoids the same copy-drift problem the analytics team hit.
EmbeddedFixed-size circular buffers as RingBuffer<T, N> — templated on both type and capacity, both resolved at compile time with zero overhead.

Step 3A Stack class template

Push/pop works for int or string — no code change to the class.

step3_stack.cpp
#include <iostream>
#include <vector>
#include <stdexcept>
template<typename T>
class Stack {
    std::vector<T> d_;
public:
    void push(const T& v) { d_.push_back(v); }
    T pop() {
        if (d_.empty()) throw std::underflow_error("empty");
        T t = d_.back(); d_.pop_back(); return t;
    }
    bool empty() const { return d_.empty(); }
};
int main() {
    Stack<int> s;
    s.push(1); s.push(2);
    while (!s.empty()) std::cout << s.pop() << "\n"; // 2, 1
}

Run: g++ -std=c++17 step3_stack.cpp -o step3

See: 2, then 1

Generic inventory stack

A typed, exception-safe container that works for tools (strings) and serial numbers (ints) from the same class definition.

program.cpp — complete use case
#include <iostream>
#include <vector>
#include <stdexcept>
#include <string>
#include <iomanip>

template<typename T>
class InventoryStack {
    std::vector<T>  items_;
    std::string      category_;
public:
    explicit InventoryStack(const std::string& cat) : category_(cat) {}

    void add(const T& item) { items_.push_back(item); }

    T takeLast() {
        if (items_.empty())
            throw std::underflow_error("No items in " + category_);
        T item = items_.back();
        items_.pop_back();
        return item;
    }

    const T&    peekLast()  const {
        if (items_.empty()) throw std::underflow_error("Empty: " + category_);
        return items_.back();
    }

    std::size_t count()    const { return items_.size(); }
    const std::string& category() const { return category_; }
};

template<typename T>
void printStatus(const InventoryStack<T>& stack) {
    std::cout << std::setw(12) << stack.category()
              << " | items: " << stack.count() << "\n";
}

int main() {
    InventoryStack<std::string> tools("Tools");
    tools.add("Hammer");
    tools.add("Wrench");
    tools.add("Screwdriver");

    InventoryStack<int> serials("SerialNums");
    serials.add(10042);
    serials.add(10043);

    printStatus(tools);
    printStatus(serials);

    std::cout << "\nDispensing:\n";
    try {
        while (tools.count() > 0)
            std::cout << "  Took: " << tools.takeLast() << "\n";
        tools.takeLast();   // triggers underflow_error
    }
    catch (const std::underflow_error& e) {
        std::cout << "  Error: " << e.what() << "\n";
    }
}
Expected output Tools | items: 3 SerialNums | items: 2 Dispensing: Took: Screwdriver Took: Wrench Took: Hammer Error: No items in Tools
